# 给 Status姬安排一间值班室

本指南适用于 v1.0.2。需要 Node.js 22+、npm，以及一个能写入本地文件的运行目录。应用使用单实例 JSON 存储，不需要额外数据库。

## 配置小抄

复制根目录的 `.env.example` 为 `.env`。应用启动时会自动读取当前工作目录中的 `.env`；请从项目根目录启动。

| 变量 | 用途 | 默认值 / 说明 |
| --- | --- | --- |
| `PORT` | 监听端口 | `3000` |
| `NODE_ENV` | 运行环境 | 本地 `development`；部署使用 `production` |
| `SESSION_SECRET` | 会话签名密钥 | 生产环境请设置独立的长随机值 |
| `ADMIN_USERNAME` | 初始管理员名称 | `admin`，仅首次创建数据库时使用 |
| `ADMIN_PASSWORD` | 初始管理员密码 | `ChangeMe123!`，部署前替换；仅首次创建数据库时使用 |
| `MUSIC_PROVIDER` | 初始音乐平台 | `netease` 或 `qishui`，之后可在后台切换 |
| `MUSIC_API_BASE_URL` | 兼容音乐 API 地址 | 留空使用内置直连；指定后由适配服务处理音乐请求 |

更换 `.env` 中的用户名和密码不会重置已有账号。会话只保存在内存中，服务重启后需要重新登录。

已有账号请在后台「页面与通知 → 后台安全」修改用户名或密码。

## 宝塔部署

1. 安装 Node.js 22 或更高版本，在 Node 项目管理中使用项目根目录作为工作目录。
2. 执行 `npm ci --omit=dev`，复制并编辑 `.env`，设置 `NODE_ENV=production`、管理员密码和会话密钥。
3. 启动文件为 `server.js`，启动命令为 `npm start`，默认端口为 `3000`。
4. 为站点配置 HTTPS 反向代理，目标设为 `http://127.0.0.1:3000`。数据库与 `.env` 不放入静态网站目录。
5. 确保运行用户可以创建、写入和重命名 `data/` 中的文件，并限制外部直接访问应用端口。
6. 打开 `/admin.html`，添加服务、分类与域名，按需要配置通知和公开服务器指标。

生产模式使用 Secure 会话 Cookie，需要通过 HTTPS 登录。应用已自带轮询器，无需额外计划任务；不要启动多个实例共同写入同一数据目录。

## 使用 PM2

安装 PM2 后，在项目根目录执行：

```bash
npm ci --omit=dev
pm2 start ecosystem.config.cjs
pm2 save
```

仓库中的配置使用进程名 `status-girl`、单进程 fork 模式和生产环境。端口如需调整，请同时修改 `.env` 与 PM2 配置，保持一致。

更新完成后可重启：

```bash
pm2 restart status-girl
```

## Nginx 反向代理

在已配置证书的 HTTPS 虚拟主机中加入：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 75s;
}
```

这只是代理片段，域名、证书与 HTTP 到 HTTPS 跳转需要在站点配置中完成。当前应用未启用 `trust proxy`，代理后的接口限流按代理连接地址统计；多人访问可能共享额度，不应直接把任意 `X-Forwarded-For` 当作可信来源。

## 通知与音乐

在后台「页面与通知」保存 SMTP 与 Webhook。通知根据状态变化或到期提醒窗口触发；域名到期日需手动登记，系统不会自动查询注册商。

音乐是可选功能。在「音乐工作台」选择平台并扫描二维码。网易云使用网易云音乐 APP；汽水当前官方二维码提示使用已登录的抖音 APP 验证身份。上游接口、账号播放权限和地区限制可能影响扫码或播放，平台返回的错误会显示在页面中。连接流程、适配服务路由及验证范围见 [音乐扫码连接](MUSIC-AUTH.md)。

默认直连不需要单独启动音乐服务。若指定 `MUSIC_API_BASE_URL`，请使用与所选平台路由及返回格式兼容的服务；切换平台时也应确认该地址对应的平台。

Linux 上不需要为扫码安装 Chromium 或 Chrome。汽水的官方请求签名由当前后台浏览器按需计算，服务器负责连接和保存会话；扫码期间保持后台打开。浏览器需能访问汽水官方组件 CDN，具体域名与异常说明见 [音乐扫码连接](MUSIC-AUTH.md)。

## 备份与更新

需要备份 **`.env` 与整个 `data/`**。其中 `data/db.json` 包含监控配置、历史记录、账号密码哈希与音乐登录态，不能作为公开演示文件分享。

备份和升级前先停止应用，保存完整的数据目录，再更新代码、执行 `npm ci --omit=dev` 并启动。不要用空数据库替换原文件。更新后检查服务列表、事件和登录状态是否符合预期。

从 v1.0.1 起，登录后台后会检查 GitHub 正式版本和标签，并在后台打开期间每 10 分钟检查一次。有新版时显示版本与更新说明，可前往更新、稍后提醒或忽略此版本；是否升级由你决定。GitHub 暂时不可用时，监控仍照常运行。

v1.0.0 用户需要先手动升级一次，才能获得这项提醒。在使用 Git 的部署目录中，确认代码没有自行修改后，可执行 `git pull --ff-only origin main` 更新；使用压缩包部署时，从版本页面下载新版并保留 `.env` 和 `data/`。

## 她的能力范围

- 默认每 300 秒检查一次，后台可调整，最短 60 秒；完整一轮结束后安排下一轮，耗时较长的目标会延长实际检查周期。
- 检查历史默认保存 7 天，最多 30 天；事件接口检索范围和分页方式见 [接入说明](API.md)。
- 服务器指标来自宿主系统。不同操作系统支持程度不同；CPU 显示核心数和系统负载，部分平台的磁盘信息可能不可用。
- JSON 文件只适合单实例使用，暂不支持多进程共享写入、分布式探针或集群调度。
- 状态页是公开页面，启用服务的地址和公开指标可以被访客读取。仅添加适合公开的目标，并按需要关闭资源展示。
- 随机壁纸与 Google Fonts 会触发浏览器外部请求；天气使用外部天气服务。可在后台配置自己的背景源。
